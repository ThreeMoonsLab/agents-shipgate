# Replayable incident shapes

These constructed fixtures map public incident shapes to the output of the
released Agents Shipgate verifier. They do not copy vulnerable vendor code,
connect to external services, or claim that Agents Shipgate was deployed in
the original incident.

**Two of the three postdate every published release.** The newest published
release is `v0.15.0`, which bundles `agent_weakens_gate` and nothing else from
this suite, so run all three from a source checkout:

```bash
./shipgate fixture run agent_weakens_gate
./shipgate fixture run governed_edits_governance
./shipgate fixture run prompt_change_rides_release
```

`agent_weakens_gate` alone also runs with no checkout, on the published
release: `uvx agents-shipgate fixture run agent_weakens_gate`. After a release
carries the other two, pin that release explicitly —
`uvx agents-shipgate@<version> fixture run <name>` — rather than naming a
version the index does not have, which fails at install before any fixture
runs.

| Fixture | Public shape | Current real output |
| --- | --- | --- |
| [`agent_weakens_gate`](agent-weakens-gate.md) | An agent bypasses or removes its own gate. | `blocked` |
| [`governed_edits_governance`](governed-edits-governance.md) | The governed agent edits its governance file. | **Expected-fail:** `mergeable`; the missing `.github/agents/**` surface is tracked in [#474](https://github.com/ThreeMoonsLab/agents-shipgate/issues/474). |
| [`prompt_change_rides_release`](prompt-change-rides-release.md) | A prompt-surface change rides beside routine release metadata. | `human_review_required` |

The CLI creates a temporary base/head Git history and runs the normal verifier.
`verifier.json` and `report.json` are generated by the engine on every replay;
no verdict is mocked or stored as a hand-edited demo result.

For the next public incident, start with the
[`response-article-template.md`](response-article-template.md). The
[`filled example`](filled-example.md) shows the intended level of evidence and
scope discipline.
